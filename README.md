# Govee lights for ChatGPT

An **unofficial, self-hosted MCP integration** for one household’s Govee lights. MIT-licensed original code. Start in a fully simulated demo without an API key, then connect your own supported lights privately.

**Status:** working local MVP with automated tests. Not deployed, not tested against real hardware, and not submitted to the ChatGPT plugin directory. This experimental source release does not establish permission to operate a public hosted integration or submit it to a plugin directory. Govee’s API terms and the host platform’s unofficial-integration rules need separate review. This project is not affiliated with Govee or OpenAI.

## What works

Eight tools provide discovery, cloud state, power, brightness, RGB color, white temperature, scene discovery and scene selection. Controls are limited to `devices.types.light` and capabilities actually advertised by each device. Other appliances are never controlled. User-facing light and scene IDs are generated by the server, not guessed by the model.

- Official Govee router API, with fixed upstream host and blocked redirects.
- No secrets in MCP tool inputs, tool results, URLs or application logs.
- A fake “Demo house lights” device for testing without touching hardware.
- Streamable HTTP and stdio MCP transports using the official MCP SDK.
- OAuth JWT validation and explicit identity/scopes for live HTTP.
- Bounded requests/responses, caching, conservative process-local pacing and no automatic write retries.
- Cancelled or stale queued writes are discarded before dispatch.

## Private desktop plugin

The `plugin/` directory contains portable and compatibility manifests, the Govee skill, and a Windows local-marketplace registration helper. Build the ready-to-run package with:

```sh
npm ci
npm run test:plugin
```

Use the resulting `desktop-package/` folder, not a source-code ZIP. It includes the bundled server and JavaScript dependencies; end users do not need npm or a build step. Follow [Windows installation](plugin/INSTALL-WINDOWS.md). Node.js 22+ is required; the helper can use ChatGPT’s existing local Node runtime. By default it controls only simulated lights.

The desktop entry point reads optional private configuration from `%APPDATA%\GoveeChatGPT\config.json` on Windows, or `~/.config/govee-chatgpt/config.json` elsewhere. This file can contain a plaintext Govee key; keep it private and outside Git/shared folders. It is not included or created by installation. The source-server setup below instead uses environment variables.

## Try the source-server demo

Requires Node.js 22 or later and npm.

```sh
npm ci
npm run check
npm start
```

This starts the **demo only** at `http://127.0.0.1:3000/mcp`. `GET /healthz` is a health check. The MCP endpoint uses POST with Streamable HTTP negotiation; it is not a REST lighting endpoint. Use an MCP-compatible client to initialize and call tools.

Example requests to a connected assistant:

- “List my Govee lights.”
- “Set Demo house lights to 30% brightness and warm white at 2700 K.”
- “Show the available scenes for Demo house lights.”

For a stdio MCP client, configure a process with command `node`, arguments `[/absolute/path/to/govee-chatgpt/dist/index.js]`, and environment `MCP_TRANSPORT=stdio`, `GOVEE_MODE=demo`. stdout is reserved for MCP; startup messages go to stderr.

## Use your own lights privately

1. Review [Govee’s API terms](https://app-h5.govee.com/common/api-service-item) and [official API-key instructions](https://developer.govee.com/reference/apply-you-govee-api-key). Do not assume this code’s MIT license grants rights to Govee services, branding or public redistribution of an integration.
2. Supply a Govee API key **only in your own process environment or private secret manager**. Do not paste it into ChatGPT, a GitHub issue or an MCP argument. This project has no web form to collect anyone’s keys.
3. Copy `.env.example` to `.env` locally and configure `GOVEE_MODE=live`, `MCP_TRANSPORT=stdio`, and your key. `.env` is gitignored. Consider a `GOVEE_ALLOWED_DEVICES` allowlist.
4. Run `npm start` from a local stdio MCP client. Alternatively, use the protected HTTP setup below.
5. Read discovery and state first. Verify your model appears and its capabilities match expectations before explicitly requesting a control. Keep the Govee Home app available to check physical behavior.

**Key rotation warning:** Govee’s May 15, 2026 policy says generating a new API key invalidates all previous keys. This can break existing home integrations. [Official notice](https://developer.govee.com/changelog/important-policy-update-important-notice-regarding-api-key-security-management)

## Connect to ChatGPT

Current [official custom MCP setup](https://developers.openai.com/api/docs/guides/custom-mcp-server) supports a remote server URL or Secure MCP Tunnel. Account/workspace availability and permissions vary.

### Private tunnel path

A [Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels) can connect a private stdio MCP process without inbound ports. Follow the official tunnel setup and restrict tunnel access to your own authorized workspace/user. This repository does **not** create a tunnel, runtime key or access grant. The private stdio server relies on process/tunnel access control, so anyone who can use that tunnel can control the configured household.

### Protected remote HTTP path

Live HTTP deliberately refuses to start without all OAuth settings. See [docs/authentication.md](docs/authentication.md). Provide an existing, correctly configured OAuth 2.1 authorization server with PKCE, issuer discovery and a ChatGPT OAuth client. The included code is a **resource server**, not an authorization server or complete hosted account-linking service.

Expose it only behind HTTPS, then add its `https://your-host/mcp` URL as a custom MCP server and configure OAuth in ChatGPT. Do not select “No authentication” for live lighting. ChatGPT does not support pasting a custom API key as connection authentication. Never expose the unauthenticated local demo as a route to real devices.

## Tools

| Tool | Purpose | Required OAuth scopes |
| --- | --- | --- |
| `list_lights` | Discover allowed lights and supported ranges | `govee:read` |
| `get_light_state` | Read cloud state; unknown fields remain null | `govee:read` |
| `set_light_power` | Explicit on/off | `govee:read govee:control` |
| `set_light_brightness` | 1–100%, further constrained by device range | `govee:read govee:control` |
| `set_light_color` | Solid RGB, each component 0–255 | `govee:read govee:control` |
| `set_light_temperature` | White Kelvin within advertised range | `govee:read govee:control` |
| `list_light_scenes` | Static and dynamic `lightScene` options | `govee:read` |
| `set_light_scene` | Choose an exact previously listed scene ID | `govee:read govee:control` |

A successful write means **Govee accepted the command**, not that the physical lights were observed changing. Cloud state can lag. On a timeout, the outcome may be unknown: read state rather than retrying blindly. Tool annotations help the client request confirmation but are not themselves authorization.

## Limits and next steps

- One process, one Govee account, one household. No shared multi-tenant deployment.
- Actual support depends on device model, firmware, region, account and Govee API capabilities. No physical outdoor-light model has been hardware-tested.
- No schedules, music, DreamView, segment controls, arbitrary capability passthrough or DIY scenes.
- No custom ChatGPT UI yet; the MVP is conversational tools.
- No OAuth authorization server, public hosting, secret onboarding or directory submission included.
- Cache: devices 60 seconds; scenes 5 minutes. No background polling. One replica per API key; other integrations using the same key can still cause rate limits.
- Public release and service use need a terms/permission review. Public ChatGPT directory eligibility is a separate question from whether MCP works privately.

See [architecture and roadmap](docs/architecture.md), [security](SECURITY.md), [protocol sources](docs/protocol.md), and [contributing](CONTRIBUTING.md).

## Development

```sh
npm ci
npm run check
npm run test:plugin
npm audit --omit=dev
```

`check` runs strict TypeScript checking, automated tests and a production build. Tests use fake Govee responses, generated ephemeral **test-only** signing keys, and a real local MCP HTTP client. They do not call Govee or change lights. There is no OpenAI API dependency or inference API key requirement.
